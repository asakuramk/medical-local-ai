**対象システム**：院内AIサーバー（Mac mini）
**作成者**：システム管理者

> **まず確認してください**
> このマニュアルはAIシステムに異常が起きたときの対応手順です。
> AIが使えなくても、**通常の手入力で業務は継続できます。**
> 慌てずに以下の手順に従ってください。

## 【対応A】サーバー障害・システム停止

### A-1. まず確認すること

```
□ ダッシュボード（http://100.64.x.x:19999）が開かない
□ AIへの入力が返ってこない
□ iMessageに「Ollamaが停止」と通知が届いた
```

### A-2. 自動復旧を待つ（5分）

システムは**自動的に再起動する設定**になっています。
まず5分待ってから再度確認してください。

```
5分後にダッシュボードを確認
    ↓
復旧した → そのまま業務再開
復旧しない → A-3へ
```

### A-3. システム管理者に連絡

```
連絡内容：
「AIシステムが○時から使えない状態です。
 ダッシュボードが（開く / 開かない）。
 iMessageのアラート内容：[内容を転送]」
```

システム管理者が遠隔で対応します（スマートフォンから操作可能）。

### A-4. 業務の継続方法（AIなしで対応）

**AIが使えなくても業務は止まりません。**

| 通常時 | AI停止時 |
|:-------|:---------|
| 音声 → AI整形 → 電カル | 音声 → AmiVoiceのみ → 手入力 |
| 整形テキストをコピー | 従来どおりの手入力 |

> AIはあくまでも補助ツールです。使えない間は従来の方法で対応してください。

## 【対応B】セキュリティアラート対応

### B-1. アラートの種類と緊急度

| アラート文言 | 緊急度 | 対応 |
|:-----------|:-------|:-----|
| 「メモリ使用率が○%」 | 🟡 低 | システム管理者に報告。経過観察 |
| 「Ollamaが停止しています」 | 🟡 低 | 5分待って自動復旧を確認 |
| 「不審な外部通信を検知」 | 🔴 高 | **即座にB-2へ** |
| 「CRITICAL」を含む通知 | 🚨 最高 | **即座にB-2へ** |

### B-2. 不審通信を検知した場合（最重要）

**発見したら迷わず以下を実行してください。**

```
ステップ1：システム管理者に今すぐ電話する
    ↓
ステップ2：システム管理者の指示を待つ
    ↓
（システム管理者が遠隔でサーバーを停止します）
    ↓
ステップ3：IT担当者に報告する
    ↓
ステップ4：事務長に報告する
```

> ⚠️ **自分でサーバーの設定を変更しないでください。**
> 証拠が消えてしまう可能性があります。
> システム管理者に連絡して指示を待ってください。

### B-3. システム管理者が不在の場合

```
システム管理者に連絡がつかない場合：
  ↓
IT担当者に連絡
  ↓
IT担当者も不在の場合：
  ↓
サーバーの電源ケーブルを抜く
（物理的に停止させる）
  ↓
事務長に報告
```

## 【対応C】システム管理者による遠隔対応手順

*（システム管理者のみ参照）*

### iPhoneからSSHで接続

```
1. iPhoneの「Termius」アプリを開く
2. 「院内LLM」を選択して接続
3. 以下のコマンドを実行
```

### 状態確認

```bash
# Ollamaの状態確認
pgrep -x "ollama" && echo "動作中" || echo "停止中"

# ネットワーク接続確認（不審な接続がないか）
sudo lsof -i -n -P | grep ESTABLISHED

# ログ確認（直近50行）
tail -50 /var/log/llm_monitor.log
```

### 段階的な対応コマンド

```bash
# レベル1：Ollamaだけ再起動
pkill ollama
sleep 5
ollama serve &

# レベル2：サービス全体を再起動
sudo launchctl stop com.hospital.ollama
sudo launchctl start com.hospital.ollama

# レベル3：ネットワークを遮断（不審通信時）
sudo pfctl -e -f /etc/pf.conf

# レベル4：Mac miniを完全停止（最終手段）
sudo shutdown -h now
```

### 復旧後の確認チェックリスト

```
□ Ollamaが起動しているか確認
□ ダッシュボードが表示されるか確認
□ テスト入力で正常に返答が返るか確認
□ ログに異常な記録がないか確認
□ 不審な外部接続がないか確認
□ スタッフに復旧連絡を送る
```

## 【対応D】よくあるトラブルと対処法

### D-1. AIの返答がおかしい（医療的に誤った内容）

```
対処：
□ そのテキストは使用しない
□ 手入力で電カルに記載する
□ システム管理者に事象を報告する（プロンプト改善のため）
```

> **AIの出力は必ず確認してから使用してください。**
> 確認せずそのまま電カルに貼り付けることは禁止です。

### D-2. 返答が非常に遅い（1分以上）

```
対処：
□ そのまま待つ（処理中の可能性）
□ 2分以上待っても返ってこない場合は手入力に切り替え
□ システム管理者に報告（後日改善）
```

### D-3. ダッシュボードのURLが開けない

```
確認事項：
□ 院内ネットワークに接続しているか
□ URLを正確に入力しているか（http://100.64.x.x:19999）
□ ブラウザを変えて試す
□ 改善しない場合はシステム管理者に連絡
```

### D-4. iMessageアラートが届かなくなった

```
対処：
□ 自分のiMessageが正常に動作しているか確認
□ システム管理者に確認を依頼（通知設定の確認）
```

## 報告書の書き方

障害・セキュリティアラートが発生した場合、以下の形式でシステム管理者へ報告してください。

```
【AIシステム障害報告】

発生日時：○月○日 ○時○分
発見者：
発見場所：
状況：（ダッシュボードが開かない / アラート内容 / その他）
その後の対応：（5分待った / システム管理者に連絡 / 電源を切った 等）
業務への影響：（なし / ○時間使用できず 等）
```

## やってはいけないこと

```
❌ AIの出力を確認せずそのまま電カルに貼り付ける
❌ 不審アラートを無視して業務を続ける
❌ 自分でサーバーの設定を変更する
❌ 外部のUSBメモリをサーバーに挿す
❌ サーバーのパスワードを他人に教える
❌ ダッシュボードのURLをSNSや外部メールで共有する
```
